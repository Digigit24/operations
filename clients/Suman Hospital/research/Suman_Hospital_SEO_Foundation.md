# 0. EXECUTIVE SUMMARY — WHAT THE DATA ACTUALLY SAYS

The honest summary first. Three findings rewrite the strategic priority order from v2.

### Finding 1 — The website is essentially dead in search since April 8, 2026.

For the 46 days from **Feb 21 to Apr 7**, sumanhospitalmoshi.com averaged **41.8 impressions/day** in Google. For the 43 days from **Apr 8 to May 20**, it averaged **0.67 impressions/day** — a **98.4% drop**. Total clicks across the entire 90-day window: **27**. Total clicks since April 8: **zero**. This is not a soft decline. The site has been de-indexed, penalized, or had a critical technical break around April 7. Diagnosing and fixing this is the single most important SEO action, ahead of every keyword, page, and content recommendation in this document.

### Finding 2 — The GBP carries the entire business. The website is a vestigial layer.

In the same 90-day window, the **GBP profile generated 7,385 impressions (3.79× the website), 328 phone calls (12× the website's 27 clicks), 1,144 direction requests, and 67 website clicks**. The hospital's local search business runs almost entirely through GBP. Only 67 out of 7,385 GBP impressions ever clicked through to the website — meaning **99.1% of patient discovery journeys never touch sumanhospitalmoshi.com at all**. Strategic implication: the GBP profile is the brand's primary digital surface; the website is the support layer. The investment ratio in v2 was inverted.

### Finding 3 — The real specialty demand is cardiology, not the v2 ordering.

GBP search keywords reveal that "cardiologist near me", "heart specialist near me", "heart hospital near me", "cardiology hospital near me", "2d echo test near me", "ecg test near me", and "heart specialist hospital" together vastly out-volume the diabetes and orthopedic queries that v2 emphasized. **Cardiology should be the #1 specialty landing page priority, not #5.** The GBP business name itself includes "Cardiologist" — Google is already routing cardiac queries to this listing. The website is failing to capture the same demand because no cardiology service page exists or is indexed.

These three findings reset the priority order for everything below.

# 2. THE WEBSITE INDEXING CRISIS — DAY 0 PRIORITY

The April 8 cliff is the single most important item in this document. Before any content, page, or keyword strategy can produce returns, the underlying indexing problem must be diagnosed and resolved.

## 2.1 What We Know From the Data

- **Last day of normal indexing:** April 7, 2026 (60 impressions)
- **First broken day:** April 8, 2026 (0 impressions)
- **State today:** 0.67 impressions/day, mostly 0–1, occasionally 4–9
- **Clicks since April 8:** 0
- **Pages still appearing:** Only the homepage, in fragments
- **GBP unaffected at the same severity:** confirms this is a website-layer event, not a brand penalty

## 2.2 Hypotheses to Investigate (in priority order)

1. **Robots.txt change** — a deploy on or near April 7 may have added a `Disallow: /` or noindex header. **Action:** check the current robots.txt and any sitewide meta-robots configuration.
2. **DNS or hosting incident** — domain may have been intermittently unreachable, prompting Google to deindex. **Action:** check uptime logs and DNS history for early April.
3. **SSL/HTTPS certificate failure** — expired or invalid cert would prevent Google from crawling. **Action:** verify cert validity history.
4. **Manual action / security issue** — check Google Search Console → Security & Manual Actions for any flagged messages dated April 7–10.
5. **Migration / redirect chain break** — if the legacy domains (sumanhospitalpcmc.com, sumanmultispecialityhospital.com) were redirected or unredirected around that date, it could have broken canonical signals. **Action:** check the redirect status of all three domains.
6. **Site replaced / accidental wipe** — a CMS-level event (theme change, plugin update, server migration) may have removed content. **Action:** verify the site is currently rendering correctly on both mobile and desktop, and that the indexed page (the homepage) still contains the same content Google last saw.
7. **Google Search Console coverage report** — should immediately show the cause via the "Pages" report (excluded reasons, indexing failures, crawl errors).

## 2.3 First-Hour Actions (Day 0 of the Foundation)

- [ ] Open Google Search Console → Coverage / Pages report → screenshot all "Why pages aren't indexed" reasons as of today
- [ ] Open GSC → Security & Manual Actions → confirm clean
- [ ] Fetch `https://sumanhospitalmoshi.com/robots.txt` and read the contents
- [ ] Fetch `https://sumanhospitalmoshi.com/` and inspect the `<meta name="robots">` tag, HTTP response headers, and HTTPS cert status
- [ ] Check whether the homepage HTML still contains the content Google previously indexed (or whether the page is now empty / replaced)
- [ ] Pull a `site:sumanhospitalmoshi.com` query in Google directly — count how many URLs Google still has in its index
- [ ] Check `whois` on the domain — confirm registration is not expired
- [ ] Identify the engineering / web-host owner for sumanhospitalmoshi.com and route the diagnosis to them
- [ ] Until indexed pages are restored, **do not** invest in writing new service pages — they will not get indexed either

## 2.4 If The Underlying Cause Is Unrecoverable

If the diagnosis reveals an unrecoverable issue (hosting account lost, CMS corrupted, content irretrievable), the recovery path is to:

1. Rebuild the site fresh on the same domain (sumanhospitalmoshi.com).
2. Re-submit a clean XML sitemap.
3. Request indexing of priority URLs through GSC's URL Inspection tool.
4. Expect 4–8 weeks for impressions to recover to pre-April-7 levels, then exceed them with the new content architecture.

Skipping this section will make every other section of this document academic. The architecture must be diagnosable, crawlable, and indexable before anything else can compound.
